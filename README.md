# VELOUR

A premium minimal fashion eCommerce storefront — Next.js (App Router) + TypeScript, no CSS framework.

```bash
npm install
npm run dev            # http://localhost:3000
npm run build && npm start
```

## Structure

```
app/                       routes, root layout (Navbar/Footer/providers), globals.css (design system)
components/                shared + page-level components (server by default; "use client" only where needed)
lib/data.ts                Product type, CATEGORIES, BASE_PRODUCTS (demo), PRODUCTS (active catalogue), subcategoriesFor()
lib/generated-products.ts  imported listings — regenerated by the import script, never hand-edited
lib/api.ts                 async service layer querying the InsForge database
lib/insforge.ts            InsForge client and admin client setup
lib/stripe.ts              Stripe client helper and initialization
lib/store.tsx              cart context + localStorage persistence + cloud cart sync
lib/format.ts              money() + shipping helpers
scripts/import-listings.mjs  CSV → products importer
scripts/verify-stripe-e2e.mjs Stripe payments end-to-end verification script
```

Routes:
- `/` — Homepage with video hero, featured & trending showcases, new arrivals, promotional banners.
- `/women`, `/men` (`?sub=…&sort=…`) — Product listings with URL filter/sort state.
- `/product/[id]` — Product detail with gallery, size selection, quantity, and related products.
- `/search?q=…` — Search results.
- `/cart` — Line items, quantities, shipping calculation, order summary.
- `/checkout` — Contact & shipping form, trusted price calculation, redirects to Stripe payment.
- `/payment/[orderId]` — Stripe checkout interstitial page.
- `/payment/return?session_id=…` — Payment confirmation, session validation, cart clearance.
- `/login` — Account sign in and registration.
- `/profile` — Account overview, order history with 4-stage tracker (Pending → Confirmed → Shipped → Delivered), payment status badge, and Pay Now links.
- `/api/orders` — Trusted order creation endpoint.
- `/api/checkout-session` — Authenticated Stripe Checkout Session generator.
- `/api/payment/confirm` — Server-side Stripe session verification.
- `/api/webhooks/stripe` — Stripe webhook handler with raw body signature verification.

### Stripe Payment Flow

1. **Order Creation (`POST /api/orders`):** When placing an order, prices and totals are calculated strictly on the server against the database product catalog. Client-submitted prices are ignored. Orders are created with `status = 'pending'`, `payment_status = 'unpaid'`, and `payment_method = 'stripe'`.
2. **Checkout Interstitial (`/payment/[orderId]`):** Authenticated check ensures only the order owner can pay. Calls `/api/checkout-session` to generate a Stripe Checkout Session with `client_reference_id` and metadata `order_id`.
3. **Payment Completion (`/payment/return` & `/api/webhooks/stripe`):**
   - Validates the Stripe Checkout Session server-side.
   - Verifies the paid amount and currency match the stored order total.
   - Transitions order status to `confirmed` and `payment_status = 'paid'`.
   - Clears the user's cart in storage and database.
   - Idempotent: repeated callbacks or visits will not duplicate charges or regress an order that is already `shipped` or `delivered`.
4. **Order Status Lifecycle:**
   `pending` (unpaid) → `confirmed` (paid) → `shipped` → `delivered`.
   Database trigger (`trg_check_order_immutable_fields`) prevents client-side tampering of order ownership, items, or pricing.

### Testing Stripe Webhook Locally

You can test Stripe webhooks locally with the Stripe CLI:

```bash
# 1. Listen for Stripe events and forward to your local route
stripe listen --forward-to localhost:3000/api/webhooks/stripe

# 2. In another terminal, trigger a test checkout event
stripe trigger checkout.session.completed
```

### Automated E2E Verification

To verify the complete database migration, pricing calculation, Stripe session creation, webhook verification, and profile tracking:

```bash
node scripts/verify-stripe-e2e.mjs
```

## Store Owner Dashboard

A minimal, secure dashboard accessible strictly to the store owner:

- **Route 1: `/admin` (Products Management):**
  - Full product catalog table with live search and category filters.
  - Add new products with validation (title, category, subcategory, prices, sizes, and multiple images with direct upload to InsForge storage).
  - Edit existing product details (pricing, compare-at pricing, description, badges for Featured/New/Trending, sizes, images).
  - Delete products with confirmation.
- **Route 2: `/admin/settings` (Website Content Settings):**
  - Update top Announcement Bar message.
  - Update homepage Promotional Banners (Shipping Banner & Sale Banner headlines, eyebrows, and copy).
  - Update Client Care contact details (Email, phone, studio address, hours) applied dynamically across `/contact`.
  - Update Brand Social Media links (Instagram, X/Twitter, Pinterest, Facebook, YouTube) applied dynamically across the site footer.
  - Full validation on email formats, required text, and URLs.

### Access Control
- Hidden from regular customers and public visitors.
- Protected server-side and client-side by checking the store owner's authenticated email against `ADMIN_EMAIL` (`razaa.komal@gmail.com`).
- Unauthorized users or visitors attempting to access `/admin` or `/admin/settings` are redirected or shown an access-denied gate with no sensitive data exposed.
- When logged into the store owner account, a dedicated **Store Owner Dashboard** link appears in the Profile page (`/profile`).
